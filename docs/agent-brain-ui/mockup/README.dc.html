Shell & interaction conventions

  • Left sidebar grouped Work / Context / Proposals, with Settings pinned at the bottom. Same on every screen.
  • Collapsible: a header toggle collapses the sidebar to an icon rail on desktop; below 1180px it becomes an off-canvas drawer with a scrim. Sub-items show in the expanded sidebar / drawer, not in the rail.
  • App-shell layout: fixed-height frame (strip + header fixed, content scrolls), so the sidebar stays full-height and Settings is always reachable.
  • Theme: light and dark, driven by CSS variables; dark is the demo default. Every color is a token — see the design system.
  • Few actions per spot, single-select filters, modals keep their title and close affordance fixed while the body scrolls.

Concepts the UI must keep distinct

These come from F025. The UI's job is to never collapse two of these into one green light.

Work status ≠ Integration statusProgress on the task vs. whether it reached the target branch.
Workspace ≠ Integration targetThe .planner/ worktree vs. the branch work integrates into.
Rules read ≠ Code conformsConventions were loaded vs. the code actually follows them.
Test passed ≠ Still relevantA check is green vs. it still covers the current code.
Resolved ≠ ReviewedAn anchor points at code vs. a human confirmed it (pending / invalidated / stale).
Verified ≠ UncertainRelations confirmed by resolution vs. only inferred.
Measured ≠ EstimatedContext cost is measured after delivery, not guessed up front.
Saved ≠ Draft ≠ HistoryThree distinct states; agent edits during yours are kept side by side.

Implementation notes

  • Build with your own component library and design tokens — the companion Agent Plan design system artifact holds the token values (tokens.json) and brand book; don't port this mockup's markup.
  • Each board here is a standalone HTML artboard (no shared partials — a canvas limitation), so header/sidebar are duplicated on purpose. In the real app they become one Shell component.
  • Theme is CSS variables with a .t-dark class on the root; mirror that split in your token layer.
  • The existing plan-web-ui package already has the faceted search, status rollups and dashboard analytics referenced here — reuse them.
